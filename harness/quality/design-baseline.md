# デザイン・ベースライン

UI（画面）を持つ機能を実装・結線するときに、`feature-builder` / `integrator` が読む。
`frontend-design`（Anthropic公式プラグイン）が利用可能なら、それが優先的な指針になり、これは
その土台として常に効く最低ラインになる。`frontend-design` が無い環境でも、これを守れば
「AIが作った没個性なデザイン」を避け、一定水準の見た目に揃えられるようにする。

各項目は数値・具体名を伴う命令形で書く。「見た目を整える」のような抽象的な指示では実装時に
判断がぶれるため、可能な限り測れる基準にしている。

## 1. そのアプリの主題に根ざした配色にする

- 実装前に、このアプリ・機能のテーマに合う基調色を 1 つ決め、そこから補色・アクセント色を
  導出する。`design.md` にテーマ・基調色が書かれていればそれに従う。
- **避けるパターン**: 暖色系のクリーム背景＋テラコッタ/オレンジ系アクセントという組み合わせを
  何のテーマとも無関係に既定色として使わない（AIが理由なく選びがちな没個性パターン）。
- 背景色・前景色（テキスト）のコントラスト比は WCAG AA 基準を満たす
  （通常サイズの文字で 4.5:1 以上、18px 相当以上の太字/24px 相当以上の文字で 3:1 以上）。

## 2. タイポグラフィは一貫させる

- 本文の基準フォントサイズは 16px 相当以上にする。
- フォントファミリーはアプリ全体で 1〜2 種類に絞る（見出し用・本文用など役割ごとに固定する）。
- 行間（line-height）は本文で 1.4〜1.6 倍にする。
- 見出し・本文・キャプションなどの階層をフォントサイズ・太さで明確に区別する。

## 3. 余白とレイアウトはグリッドに揃える

- 余白（padding/margin）は 4px または 8px の倍数に統一する（バラバラな値を使わない）。
- 関連する要素同士は近づけ、無関係な要素とは離す（近接の原則）。グループごとに余白の大きさを
  変えて視覚的な階層を作る。
- 横方向の要素は揃える（左端／中央／右端のいずれかに整列させ、中途半端な位置に置かない）。

## 4. インタラクションの状態を省略しない

- クリック可能な要素には hover / focus / active / disabled の見た目の違いを用意する。
- 非同期処理には loading 状態を、データが無い場合には empty state を、失敗した場合には
  エラー表示を、それぞれ用意する（「何も起きていないように見える」状態を作らない）。
- キーボード操作でのフォーカス可視化（outline 等）を消さない。

## 5. 最低限のアクセシビリティ

- 画像には代替テキスト（`alt`）を付ける。
- フォーム要素には `label` を関連付ける。
- クリック/タップ操作の対象は 44x44px 相当以上のサイズを確保する。
- 色だけで情報を区別しない（エラーを赤色だけで示さず、アイコンやテキストも併用する）。

## 6. レスポンシブの最低ライン

- モバイル幅（375px 程度）とデスクトップ幅（1280px 程度）の両方でレイアウトが崩れないことを
  確認する。横スクロールが意図せず発生しないようにする。
